## How to claim and hand back

1. **Claim:** put your name in the `owner` column below, commit, push to `main`
   (`git pull --rebase` first). One line, so conflicts are trivial.
2. **Work on your own branch:** `team/<name>-<task id>`, e.g. `team/timo-T2`.
3. **Touch only the paths of your task.** `src/harness/`, `tests/` and `scripts/` are being
   tuned on experiments right now: changes there invalidate measurements, so do not edit them
   (task T3 reports problems instead of fixing them).
4. **Hand back:** push your branch and tell Elias (or open a PR into `main`). Docs-only tasks
   (T1, T4, T5) may be merged into `main` directly once done.
5. **Money:** the OpenAI key is shared (~150 CHF in total, ~$18 used). **No harness runs
   without asking**: none of these tasks needs one.

## T2 A fresh exam game

**Why:** we tune on 6 games and hold out 2 (zeta, theta), but all 8 were designed by us
today. A game built by someone who has *not* looked at our prompts is the most honest exam
of how the harness does on the organisers' unseen games. We run the harness on it once, at
the end, and never tune on it.

**Goal:** one (or two) new games of the family as an arena game package under
`testgames/<name>/` (pick a name not yet used, e.g. `iota`, `kappa`). Same family invariants
(2 players, simultaneous moves, units on graph nodes, nodes carry demand, Python-literal
observations/actions), but at least one mechanic none of the existing games has. **Do not
read `src/harness/prompts/`** (so the game is not shaped by our prompts).

**Done when:** `spec.md` is as complete as `arena_games_dev/beta/spec.md` (an LLM can write a
simulator from it alone; worked examples with exact observations, generated by running
`game.py`), baselines pass `arena check`, the greedy baseline beats random, tests pass.

**Prompt for Claude Code:**

```
In this repository, read docs/TASK.md (sections 3-4 and the appendices) and study the dev
games in .venv/Lib/site-packages/arena_games_dev/{alpha,beta}/ (spec.md, game.py,
baselines.py, __init__.py) and .venv/Lib/site-packages/arena/core.py. Look at one of
testgames/gamma or testgames/epsilon for the package structure only. Do NOT read
src/harness/prompts/ or src/harness/.
Build a NEW game of the same family as an arena game package testgames/<name>/ (a name not
used yet): __init__.py exporting GAME, BASELINES, SPEC like the dev packages; game.py
(subclass arena.core.Game, deterministic per seed, never raises on any action value, None is
a no-op); baselines.py (DoNothing, RandomStrategy with legal random actions, one greedy
baseline); spec.md in the same style and completeness as beta's spec.md (constants block,
observation schema, strict action format with malformed vs illegal, scoring with formulas,
worked examples with EXACT observations generated by running game.py, end of game,
tournament and ranking text like the dev specs); test_game.py checking the worked examples
against spec.md and determinism. Include at least one mechanic none of the games in
testgames/ has. Validate: arena check for every baseline, arena run of the baselines
(10 seeds), arena make-task --game testgames.<name> ... must work. Touch nothing outside
testgames/<name>/. Do not run the harness.
```

unattended in a Linux container (read-only root, only `/output` and `/tmp` writable,
unprivileged user, 2 CPUs, no network except the OpenAI endpoint, SIGTERM at the deadline),
and its strategies run in arena's isolated worker (1 s per act, bare Python 3.13).

**Done when:** `docs/review-<name>.md` lists concrete findings (file:line, failure scenario,
severity, suggested fix), most severe first. **No code edits**: we fix them centrally.
